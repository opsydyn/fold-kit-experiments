# Effect UI 1.0 migration

Proposed for the private `effect-ui-next` worktree on 26 November 2026. The
baseline is `170be3a6`. The pilot adapts Effect UI components to Astro and
renders two datasets through the same Viz chart. Its Happy DOM checks cover
DOM adoption and scope teardown. The Chromium fixture checks deferred
activation and retained-island navigation using intercepted requests.

## Scope and release decision

Move the maintained FoldKit 0.x consumers to Effect UI. Keep the pure Viz
geometry, Effect plot composition, Three engine and ZLOZ document formats as
existing integration boundaries. Aim for a coordinated `1.0.0` release of
the ten packages currently tracked by release-please. Use `1.0.0-next.0` as
the first version to rehearse with local tarballs. Private workspaces qualify
the train through their builds and user flows.

The standalone Astro renderer remains the owner of Astro integration code.
The release candidate should test a thin Astro FoldKit entry point that
forwards to it. Write the old-to-new import and API mapping before committing
to the new entry point. Existing 0.x versions remain available to consumers
who need the legacy runtime.

A monorepo-wide version bump is useful only if real consumers can install
and run a coherent set. A FoldKit peer-range edit cannot express a dependency
on the new runtime. In particular, the current Viz Three peer excludes 1.0,
and the Three and ZLOZ sibling peers use exact versions. Release-please links
the two sibling families and uses pre-1.0 bump rules, so the major train
needs an explicit release rehearsal.

## Worktree and pull request

Develop the full migration in the existing `effect-ui-next` worktree and
deliver it in one pull request. Keep the dependency waves in reviewable
commits on the same branch. The final commit range must include the
migration guide and evidence from the coordinated version rehearsal.
The private scope covers dependency downloads and local tarballs.

The first Astro/Viz slice now renders a dot plot through Viz's merged
composition, decode and compile APIs. The fixture also renders the
structured diagnostic for a missing field. The workspace uses Effect 4.1.6
and the matching browser, Bun, Node and Vitest packages. Standalone promo
downloads take their Effect and browser platform versions from the catalog.
The pilot composes the decoded plot directly with Effect `Result` combinators. This replaced a tagged-value boundary needed when
Viz built against 4.1.0. Qualify the aligned dependencies again when the
full migration is packed for rehearsal.
