# Effect UI 1.0 migration

Proposed for the private `effect-ui-next` worktree on 26 November 2026. The
baseline is `170be3a6`. The pilot adapts Effect UI components to Astro and
renders two datasets through the same Viz chart. Its Happy DOM checks cover
DOM adoption and scope teardown. The Chromium fixture checks deferred
activation and retained-island navigation using intercepted requests.

## Scope and release decision

Move the maintained FoldKit 0.x consumers to Effect UI. Keep the pure Viz
geometry, Effect plot composition, Three engine and ZLOZ document formats as
existing integration boundaries. Aim for a coordinated `1.0.0` release of
the ten packages currently tracked by release-please. Use `1.0.0-next.0` as
the first version to rehearse with local tarballs. Private workspaces qualify
the train through their builds and user flows.

The standalone Astro renderer remains the owner of Astro integration code.
The release candidate should test a thin Astro FoldKit entry point that
forwards to it. Write the old-to-new import and API mapping before committing
to the new entry point. Existing 0.x versions remain available to consumers
who need the legacy runtime.

A monorepo-wide version bump is useful only if real consumers can install
and run a coherent set. A FoldKit peer-range edit cannot express a dependency
on the new runtime. In particular, the current Viz Three peer excludes 1.0,
and the Three and ZLOZ sibling peers use exact versions. Release-please links
the two sibling families and uses pre-1.0 bump rules, so the major train
needs an explicit release rehearsal.

## Worktree and pull request

Develop the full migration in the existing `effect-ui-next` worktree and
deliver it in one pull request. Keep the dependency waves in reviewable
commits on the same branch. The final commit range must include the
migration guide and evidence from the coordinated version rehearsal.
The private scope covers dependency downloads and local tarballs.

The first Astro/Viz slice now renders a dot plot through Viz's merged
composition, decode and compile APIs. The fixture also renders the
structured diagnostic for a missing field. The workspace uses Effect 4.1.6
and the matching browser, Bun, Node and Vitest packages. Standalone promo
downloads take their Effect and browser platform versions from the catalog.
The pilot composes the decoded plot directly with Effect `Result` combinators. This replaced a tagged-value boundary needed when
Viz built against 4.1.0. Qualify the aligned dependencies again when the
full migration is packed for rehearsal.

Wave 1 now includes build-time and request-time Astro rendering tests. The
built server accepts concurrent requests with independent props and state.
The renderer passes Astro's prerender flag into Effect UI. These tests run
in-process against the built fetch entrypoint.

Start wave 1 by routing a Viz component through the merged Viz composition
API where it fits. Keep the pilot's simple geometry fixture as a
comparison until the compiled plot adapter has equivalent behavior. The
pilot now registers `client:interaction` and tests click replay and removal
during pending activation. Chromium passed deferred activation, chart selection
by keyboard, first-click replay and retained-island navigation. Native forms
still need a browser check.

The private Astro Effect UI renderer is now a workspace package. The web
workbench and Three promo use it for the shared `chart3d` sample. Their existing
FoldKit integration owns `client:interaction` while both renderers are enabled.

Wave 2 shares the scoped scene host through the Three adapter's browser
subpath. In Happy DOM the recording renderer proves reuse on update and
release of the canvas, renderer, geometry and materials on unmount. The
Chromium fixture imports the maintained chart and verifies scene
reconciliation after orbit, a stable canvas across chart selection, WebGL
context loss on navigation and a new canvas on return. Chromium also checks
SSR, hydration and keyboard chart selection in the built Three promo site
and the web workbench's local request-rendered route. The Three browser
subpath passes the ESM tarball checks.

The web workbench and Three promo also use Effect UI for Gallery and Bowling.
Gallery measures the bundled font and resizes a plaque after a text edit.
Bowling starts its replay and settling commands after the Rapier scene is
ready. Chromium loads the font, records a roll that knocks pins down, reopens
the generated replay link and matches its pin count. Navigation releases the
WebGL context for each sample.

Workshop now uses Effect UI asset events for progressive glTF and texture
loading, sign font loading, and unload and reload. Room uses a scoped browser
environment shared by its scene and XR commands. Its presence subscription
owns the relay connection. Chromium checks progressive downloads, fresh
acquisition after unload, incoming and outgoing poses using a mocked relay,
and socket closure on navigation. The Room development dispatch and Workshop time
travel examples still need an Effect UI DevTools integration, and immersive
VR and AR require a headset check.

Bars, City, Curves, Hero, Marbles, Playground, and Sculpture now use Effect
UI on their maintained routes. The browser subpath exports the event schemas

Chromium checks deferred Hero activation and repaint, City hover and reseed,

Studio, Arrange and Toybox now use Effect UI. Their HTML overlays and

and keyboard pan, Arrange's inspector edits, undo and redo, and the
tape label, and Toybox's Rapier scene, controls and teardown.

Shared Resources now uses Effect UI in both hosts. Chromium checks that
resizing and removing a cube keep the current canvas, unmount loses its
WebGL context, and remount creates a new canvas while keeping the controls'
state.

Tabletop now uses Effect UI for the scene, commands, and keyed session
subscriptions. The relay socket belongs to its subscription, and the
Rapier worker belongs to the scene scope. Chromium checks lockstep between
a main-thread tab and a predicting worker tab, replay of a recorded throw,

The Three scene editor now uses Effect UI for its scene, inspector, files,

The web workbench's 3D Radar now uses Effect UI. Its hydrated dataset and

Polars Summary now uses the standalone Viz renderer for both request-time

The ZLOZ promo's Compose island now uses Effect UI. The core exposes a

The shared Effect UI graph surface now supports width-only node resizing and

The current package source for Effect UI documents commit-pinned preview
snapshots. A private rehearsal can use one pinned revision and compatible
Effect dependencies. A public `1.0.0` needs a reproducibly installable
upstream dependency and separate publication approval.
