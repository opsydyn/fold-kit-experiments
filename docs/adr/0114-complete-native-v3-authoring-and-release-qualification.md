# ADR 0114: Complete native v3 authoring and release qualification

Accepted, 2026-11-16, for the user-authorized completion batch in
[the fixed checklist](../specs/2026-11-16-zloz-release-completion.md).

Reuse pure graph/semantic algorithms with distinct full-document v3 validation and
native source-bound publication. Keep legacy version defaults unchanged. Extend
patch evaluation and bounded text decoding through native validation callbacks;
retain exact source/provenance, losses, live policy and one Undo. Native C4/DDD
conversion plans use the same semantic choices/containment algorithms with native
model capture and native transaction publication. Recomputed portable receipts and
review packets remain unsigned read-only evidence, never authority to Apply.

The existing shared browser input resource supplies resize/anchor/reconnect/box/
pinch facts. The native controller owns tagged transient gestures and uses the
same live planners for preview and release. No external state/DOM mutation is added
to application updates. View primitives remain composable and policy-aware.

Boundary verdict: safe with noted risk. Core owns data, intent and transactions;
adapters own wire projections; host Commands own IO/current permission. Shared
algorithms avoid a second validator or duplicate conversion semantics. A legacy
editor cast would lose group capability and is rejected as an alternative. An
all-new modelling language or parser would exceed this batch. Version-specific
wire records are necessary; widening default readers is not acceptable.

Qualification distinguishes installed/import/type, SSR/hydration, browser,
performance, remote CI and human device/AT results. No synthetic pass substitutes
for human acceptance. Prepare a finite release candidate and PR without expanding
into advanced catalogue items or publishing npm. Existing credentials and manual
publication remain a later explicit gate. Test malformed, stale, incompatible,
protected and cancellation paths plus exact portable recomputation and Undo.
Local recovery is reverting feature commits; no existing portable data is migrated.
Architecture/delivery/test-quality review is self-review unless separately recorded.
