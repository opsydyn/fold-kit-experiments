# ADR 0037: A declarative grammar of marks for foldkit-viz

## Status

**Accepted**, 2026-11-13, for foldkit-viz 0.19.0. Implements the second release of the
[data-science release track](../roadmap.md#viz-data-science-release-track--2026-11-13).
The [specification](../superpowers/specs/2026-11-13-plot-grammar-design.md) holds the
detailed contract.

## Context

foldkit-viz composes charts from geometry functions (`lineGeometry`, `barGeometry`,
`cellGeometry` and others) and FoldKit view helpers. Each chart repeats the same
assembly: pick accessors, resolve domains per axis, build ticks, colour each series
and lay out a legend. Plotly Express, Vega-Lite and Observable Plot remove that
assembly with a grammar: a chart is a list of marks whose channels map data fields
to scales, and the scales, axes and legends are inferred. That grammar is the main
reason those libraries are fast to use, and foldkit-viz has none.

Two of foldkit-viz's advantages shape the grammar. Charts render on the server with
no JavaScript, and generated or remote charts should too. And the planned reach work,
a Jupyter widget and charts written by language models, needs a chart description
another language or a model can emit.

## Decision

1. **A chart is a plain JSON-serialisable spec.** Fields are referenced by name,
   constants are `{ value }` objects, and transforms are named with options. The spec
   holds no functions, so it can be stored, sent over the wire, generated by a model
   or written from Python, and rendered the same way on a server or in a browser.
2. **Compiling is pure and framework-free.** `compilePlot(spec)` in a new `plot`
   subpath returns positioned geometry, axes and legends: no DOM, FoldKit or Effect.
   A FoldKit adapter, `foldkit/plot`, renders it with the parent's builder; a canvas
   adapter can follow in 0.20.0 from the same geometry.
3. **Scales are inferred and shared.** x, y, colour and size scales take their type
   and domain from every mark's channel values, across every facet. A spec overrides
   any part. Continuous axes reuse the 0.18.0 scale-generic layer; categorical axes
   use band scales.
4. **Errors name the path.** Invalid specs are rejected with a `RangeError` whose
   message names the location, such as `marks[1].x: field "dose" is missing`, so a
   person or a model can correct it.
5. **The geometry API stays.** The grammar is built on the existing functions and
   does not replace them; a chart that needs a function or custom drawing keeps using
   geometry directly.

## Consequences

- One spec format serves the web app, server rendering, generated charts and a
  future Jupyter widget.
- Marks that need functions, such as custom label formatters, are limited to named
  formats in the spec. That is the price of serialisability.
- The spec is public API from 0.19.0, so additions must stay backward compatible.
- foldkit-viz's root stays framework-free; only `foldkit/plot` needs FoldKit.

## Options considered

- **Accessor functions in the spec**, as Observable Plot allows. Rejected: not
  serialisable, so neither server-to-client handoff nor model or Python generation
  would work.
- **Adopting Vega-Lite's schema.** Rejected: very large, and its runtime model
  (signals, datasets, view composition) does not map onto FoldKit's parent-owned
  state. The spec borrows its vocabulary where it fits.
- **Chart presets only** (`lineChart(options)` and so on). Rejected as the
  foundation: presets do not compose into layered or faceted charts. Presets can be
  written as functions that return specs.

## Follow-up work

- Interaction in the spec (hover, selection and linked brushing) with the 0.20.0
  interaction kit.
- A published JSON Schema for the spec, for editors, models and the Jupyter widget.
- Promotions of the remaining web-app demos as marks or spec presets.

## Review date

Review at the 0.20.0 release, when the canvas adapter and interaction land.
