# Strict review-packet decoder qualification

- **result:** complete
- **claim:** portable v1 packets reopen as detached, deeply frozen data only after
  bounded JSON validation, core snapshot/identity checks and full audit/projection
  recomputation. This enables read-only host integration without importing or editing
  a live model. CLI and workbench opening integration remain subsequent work.
- **evidence:** a literal previously generated v1 packet is retained independently
  of current creation tests. Tests cover current/distinct-edition/self comparisons,
  builtin/custom catalogues, key order, escaped duplicate keys, syntax/format/version,
  unknown fields, conflicting identities, stale audit/projections/diagnostics,
  character/depth/value budgets, non-finite numbers, scalar coercion, legitimate
  metadata and frozen ownership. A compiled Node run reproduced wide-array stack
  overflow before the traversal fix; the corrected run returns `limit-exceeded`.
  Real packed Node/Bun consumers exercise opening, frozen data, forged projections
  and wide-input rejection without browser/runtime peers. Root `bun typecheck`,
  `bun run check` and `bun run test` exit 0. The Mermaid adapter has 38 passing
  tests, including 11 new decoder tests; core has 486 and workbench has 106.
  The full workspace suite has no failures. `bun run --filter @opsydyn/foldkit-zloz docs`
  exits 0 and includes the new decoder, options and result pages. See
  [the repeatable fixture](review-packet-parse-fixture.ts) and
  [captured outcomes](review-packet-parse-results.json).
- **remaining uncertainty:** validation establishes self-consistency, not author
  authenticity, signatures or trustworthy model intent. Mermaid is retained as data,
  never executed. Limits constrain shape, not wall-clock time or peak memory; host
  IO/UTF-8/file-byte limits, responsiveness/worker isolation and UI recovery still
  need host integration. No live editor, graph import, CLI command, workbench reader,
  hosted deployment, publishing, PNG or Alchemy is introduced. Architecture/boundary,
  delivery and test-quality reviews are self-review, with these format and runtime
  limits. Builtin v1 interpretation must remain stable across future releases.
- **next:** needs review — add Effect CLI validation/inspection for review packets,
  reusing this decoder and explicit exit codes. Then wire read-only workbench opening
  while preserving the last good review on failure. PNG and Alchemy stay deferred.
